# 4.4. 핵심 UX 원칙 명세서

이 문서는 신규 기능 개발 시 반드시 고려해야 할 핵심 사용자 경험(UX) 원칙을 정의합니다. 모든 UI/UX 디자인 및 구현은 아래 원칙을 최우선으로 고려해야 합니다.

---

### 1. 실시간 AI 문구 생성 기능

> **핵심 목표:** 사용자가 AI의 복잡성을 느끼지 않고, 쉽고 자신감 있게 개인화 메시지를 만들 수 있도록 돕는다.

#### **UX 원칙 1: 명확한 기대치 설정 (Clarity & Confidence)**
- **문제:** `{{llm.generate()}}`는 사용자에게 생소하고 추상적인 개념입니다. 어떤 결과가 나올지 예측하기 어려워 사용을 주저할 수 있습니다.
- **솔루션:**
    - **미리보기/테스트 기능:** 실제 발송 전, 특정 유저를 샘플로 지정하여 AI가 생성할 문구를 미리 확인하는 기능을 제공해야 합니다.
    - **직관적인 모달 UI:** `AI 문구 생성` 모달 내 각 필드(프롬프트, 타임아웃 등)의 역할과 기본값을 명확히 안내하고, 좋은 프롬프트 예시를 Placeholder나 가이드 텍스트로 제공해야 합니다.

#### **UX 원칙 2: 시스템 신뢰도 확보 (Feedback & Transparency)**
- **문제:** AI 문구 생성은 비동기로 처리되므로, 사용자는 자신의 요청이 정상적으로 처리되고 있는지 알기 어렵습니다.
- **솔루션:**
    - **상태 피드백:** 캠페인 발송 후, AI 생성 변수가 포함된 메시지들이 '처리 중', '성공', '실패(대체 문구 사용)' 등 어떤 상태에 있는지 캠페인 리포트에서 확인할 수 있어야 합니다.
    - **실패 사유 안내:** AI 문구 생성이 실패하여 대체 문구가 사용되었을 경우, '타임아웃', 'API 오류' 등 구체적인 사유를 로그에서 확인할 수 있도록 제공해야 합니다.

### 2. 이메일 상태 자동 관리 (SendGrid 연동)

> **핵심 목표:** 사용자가 이메일 상태 변화를 명확히 인지하고, 시스템의 자동화 규칙을 신뢰하며, 필요한 경우 적절히 개입할 수 있도록 한다.

#### **UX 원칙 3: 변화의 맥락 제공 (Contextual Information)**
- **문제:** `email_status`가 `active`에서 `bounced`나 `unsubscribed`로 갑자기 변경되면, 사용자는 왜 그렇게 되었는지 이해하기 어렵습니다.
- **솔루션:**
    - **상태 변경 히스토리:** 사용자 상세 페이지의 활동 피드(Activity Feed)에 "SendGrid 웹훅에 의해 email_status가 bounced로 변경되었습니다." 와 같이 상태 변경의 원인과 시점이 명확히 기록되어야 합니다.
    - **툴팁 정보:** `email_status` 뱃지에 마우스를 올리면, '2025-09-15에 수신 거부됨'과 같이 마지막 상태 변경 일시와 사유를 간략히 보여주어야 합니다.

#### **UX 원칙 4: 통제권과 안전장치 (Control & Safety)**
- **문제:** 이메일 상태를 수동으로 변경하는 기능은 편리하지만, 시스템의 자동화 로직과 충돌하여 문제를 일으킬 수 있습니다.
- **솔루션:**
    - **명확한 경고:** 상태를 수동으로 변경하려고 시도할 때, "이 상태는 웹훅을 통해 자동으로 관리됩니다. 수동 변경 시 발송에 문제가 생길 수 있습니다." 라는 명확한 경고 메시지를 표시하여 사용자가 행동의 결과를 인지하도록 해야 합니다.
    - **재구독 플로우 안내:** `unsubscribed` 상태의 유저를 `active`로 변경하려 할 때, "사용자가 직접 재구독 링크를 통해 동의하는 것이 가장 안전합니다." 와 같은 가이드를 제공하는 것을 고려해야 합니다.

### 3. 전사적 UX 원칙 (Product-Wide UX Principles)

> **핵심 목표:** 사용자가 시스템을 신뢰하고, 데이터를 안전하게 관리하며, 빠르고 효율적으로 업무를 처리할 수 있는 전문가용 도구를 제공한다.

#### **UX 원칙 5: 상태를 포함한 고유 주소 (Stateful URLs)**
- **문제:** 팀원 간에 특정 화면을 공유할 때, 현재 보고 있는 필터나 정렬 상태까지 함께 전달할 방법이 없어 비효율적인 커뮤니케이션이 발생합니다.
- **솔루션:**
    - 모든 주요 페이지(캠페인 목록, 사용자 상세 등)는 고유의 URL을 가져야 합니다.
    - 페이지 내의 상태(예: 필터링 조건, 정렬 순서, 현재 페이지 번호)가 변경될 때마다 URL의 쿼리 파라미터가 실시간으로 업데이트되어야 합니다.
    - 사용자는 이 URL을 복사하여 다른 팀원에게 공유할 수 있으며, 링크를 연 팀원은 정확히 동일한 상태의 화면을 볼 수 있어야 합니다.

#### **UX 원칙 6: 파괴적인 액션에 대한 안전장치 (Safety for Destructive Actions)**
- **문제:** 중요 데이터(캠페인, 사용자 등)를 실수로 삭제했을 때 복구하기 어렵습니다.
- **솔루션:**
    - 모든 삭제 기능에는 확인 모달(Confirmation Modal)을 적용해야 합니다.
    - 모달에는 "캠페인 '가을 할인 프로모션'을 정말 삭제하시겠습니까?" 와 같이 삭제 대상의 이름을 명확히 표시하여 사용자의 실수를 방지해야 합니다.

#### **UX 원칙 7: 명확한 시스템 피드백 (Clear System Feedback)**
- **문제:** 데이터 로딩이나 대량 작업 시 시스템이 아무런 반응을 보이지 않으면, 사용자는 시스템이 멈췄다고 오해하거나 작업 성공 여부를 알 수 없어 답답함을 느낍니다.
- **솔루션:**
    - **로딩 상태:** 데이터 로딩 중에는 스켈레톤 UI(Skeleton UI)를 표시하여 시스템이 정상 작동 중임을 알려주고 콘텐츠가 곧 표시될 것을 암시해야 합니다.
    - **대량 작업:** 여러 항목을 동시에 처리하는 작업은 비동기로 처리하고, 화면에 "N개의 항목을 처리 중입니다..." 와 같은 토스트(Toast) 알림을 표시하여 진행 상태를 알려줘야 합니다. 작업 완료 후에는 성공/실패 여부를 명확히 피드백해야 합니다.

#### **UX 원칙 8: 실수를 되돌릴 수 있는 기회 (Forgiving Interactions)**
- **문제:** 삭제와 같이 중요한 작업을 실행한 직후, 사용자가 마음이 바뀌어도 되돌릴 방법이 없습니다.
- **솔루션:**
    - 삭제, 보관(Archive) 등의 액션 후에는 데이터를 즉시 영구 삭제하는 대신, "항목이 삭제되었습니다. [실행 취소]" 와 같은 토스트 알림을 약 5-7초간 제공해야 합니다.
    - 사용자는 '실행 취소(Undo)' 링크를 클릭하여 방금 한 작업을 즉시 되돌릴 수 있어야 합니다.

#### **UX 원칙 9: 사용자 맞춤형 데이터 뷰 (Customizable Data Views)**
- **문제:** 모든 사용자에게 동일한 형태의 데이터 목록을 제공하는 것은 개인의 업무 효율을 저해합니다.
- **솔루션:**
    - 캠페인, 사용자 등 주요 목록 페이지에서 사용자가 직접 컬럼의 표시 여부(Show/Hide)와 순서를 변경할 수 있는 기능을 제공해야 합니다.
    - 이 설정은 각 사용자 계정에 개인화되어 저장되어야 하며, 언제든 초기화할 수 있어야 합니다.

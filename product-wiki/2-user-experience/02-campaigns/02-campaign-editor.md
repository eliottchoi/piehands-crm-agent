# 2.2.4. 캠페인 편집기 (Campaign Editor)

## 주요 개념 정의

- **캠페인 편집기:** 특정 캠페인의 모든 요소를 설정하는 종합적인 편집 환경입니다. 캠페인의 이름, 목표 등과 같은 메타 정보와, **캔버스**를 사용한 자동화 로직 설정을 포함합니다.
- **캔버스 (Canvas):** 캠페인 편집기 내의 핵심 영역으로, 유저의 여정을 시각적으로 설계하는 공간입니다.
- **노드 (Node):** 캔버스를 구성하는 최소 단위 블록입니다. 모든 노드의 종류와 상세 설명은 아래 '캔버스 구성요소 상세' 섹션을 참고하십시오.

- **위치:** 캠페인 목록 > 특정 캠페인 클릭 시
- **역할:** 특정 캠페인의 자동화 로직과 관련 설정을 생성하고 수정하는 핵심 공간.

---

## 캔버스 구성요소(노드) 상세

### 1. 시작 조건 (Triggers)
| 노드 이름 | 설명 | 설정 가능한 항목 |
| :--- | :--- | :--- |
| **이벤트 기반** | 특정 이벤트가 발생했을 때 여정을 시작합니다. | `이벤트 이름`, `이벤트 속성 필터` |
| **시간 기반** | 특정 시간 또는 주기에 여정을 시작합니다. | `실행 시각 (예: 매주 월요일 09:00)`, `타임존` |
| **API 호출** | 외부 시스템에서 API를 호출하면 여정을 시작합니다. | `고유 Webhook URL (자동 생성)`, `전달받을 데이터 스키마`|

### 2. 액션 (Actions)
| 노드 이름 | 설명 | 설정 가능한 항목 |
| :--- | :--- | :--- |
| **이메일 발송** | 유저에게 이메일을 보냅니다. | `템플릿 선택`, `이메일 제목`, `발신자 이름/주소`, `수신 거부 링크 포함 여부` |
| **SMS 발송** | 유저에게 SMS를 보냅니다. | `템플릿 선택`, `발신 번호` |
| **속성 업데이트** | 유저의 속성 값을 변경합니다. | `대상 속성 Key`, `변경할 Value (고정값 또는 다른 속성값)` |
| **웹훅 호출** | 외부 시스템 API로 데이터를 전송합니다. | `호출 URL`, `HTTP 메소드 (POST/PUT)`, `전송할 데이터 (JSON)` |

### 3. 흐름 제어 (Flow Control)
| 노드 이름 | 설명 | 설정 가능한 항목 |
| :--- | :--- | :--- |
| **시간 대기** | 다음 단계 전까지 일정 시간 기다립니다. | `대기 시간 (분/시간/일)`, `특정 날짜/시간까지 대기`, `유저의 타임존 기준 대기` |
| **조건 분기** | 유저의 속성/이벤트에 따라 경로를 나눕니다. | `분기 조건 (예: user.level == 'VIP')`, `최대 대기 시간` |
| **A/B/n 테스트** | 유저를 여러 그룹으로 나누어 실험합니다. | `분기 개수 (2~5개)`, `각 그룹의 트래픽 비율 (%)` |

### 기능: 캔버스 노드(Node) 관리

> **목표:** 팀 멤버는 캔버스에 시각적 노드를 추가, 연결, 설정하여 원하는 자동화 흐름을 구성할 수 있다.

**시나리오 1: 노드 추가 및 설정** (기존 시나리오 1과 동일)
`Given` 팀 멤버가 "신규 가입자 환영" 캠페인의 비어있는 '캔버스 편집' 페이지에 있다
`And` 화면 좌측에는 '컴포넌트 팔레트'가 보인다
`When` 팀 멤버가 '시작 조건 (Triggers)' 섹션에 있는 `이벤트 기반` 컴포넌트를 드래그하여 중앙 캔버스 영역에 드롭한다
`Then` 캔버스 위에 "이벤트 기반 트리거"라는 제목의 노드가 생성되어야 한다
`And` 화면 우측에는 해당 노드를 설정할 수 있는 '설정 패널'이 나타나야 한다
`And` '설정 패널'에는 "어떤 이벤트가 발생했을 때 시작할까요?" 라는 레이블과 함께 이벤트 목록 드롭다운이 보여야 한다

**시나리오 2: 노드와 노드 연결**
`Given` 캔버스에 "A: 이벤트 기반 트리거" 노드와 "B: 이메일 발송" 노드가 존재한다
`When` 팀 멤버가 "A" 노드의 하단 연결점(Handle)을 클릭한 상태로 "B" 노드의 상단 연결점까지 드래그하여 놓는다
`Then` "A" 노드와 "B" 노드 사이에 시각적인 연결선(Edge)이 그려져야 한다

**시나리오 3: 이메일 발송 노드 설정**
`Given` 팀 멤버가 캔버스 위의 `이메일 발송` 노드를 클릭했다
`And` 우측 '설정 패널'이 나타났다
`When` 팀 멤버가 패널 내 `템플릿 선택` 버튼을 클릭한다
`Then` 기존에 생성된 템플릿 목록이 모달 창으로 나타나야 한다

`Given` 팀 멤버가 "환영 이메일" 템플릿을 선택했다
`When` 팀 멤버가 `선택 완료` 버튼을 클릭한다
`Then` '설정 패널'의 템플릿 영역에 "환영 이메일"이라는 이름이 표시되어야 한다
`And` 해당 노드 데이터에 `templateId`가 저장되어야 한다

### 기능: 캔버스 저장 및 유효성 검사

> **목표:** 팀 멤버는 작업 중인 캔버스를 안전하게 저장할 수 있으며, 시스템은 로직의 오류를 방지하기 위해 유효성을 검사해야 한다.

**시나리오 4: 미완성된 캔버스 저장**

`Given` 캔버스에 `이메일 발송` 노드가 있지만, 템플릿이 선택되지 않았다
`When` 팀 멤버가 상단 바의 `저장` 버튼을 클릭한다
`Then` "저장되었습니다." 라는 토스트 메시지가 나타나야 한다
`And` 캠페인의 상태는 여전히 `DRAFT`를 유지해야 한다

**시나리오 5: 미완성된 캔버스를 활성화 시도 시 실패**

`Given` 캔버스에 `이메일 발송` 노드가 있지만, 템플릿이 선택되지 않았다
`When` 팀 멤버가 상단 바의 `활성화` 버튼을 클릭한다
`Then` 해당 노드 주변에 빨간색 테두리가 표시되어야 한다
`And` "활성화하려면 모든 노드의 설정을 완료해야 합니다." 라는 오류 메시지가 나타나야 한다
`And` 캠페인의 상태는 변경되지 않아야 한다

# 2.2.1. 로그인 및 회원가입 (Login & Sign Up)

## 주요 개념 정의

- **Firebase Authentication:** Google이 제공하는 안전하고 간편한 인증 솔루션. 이메일/비밀번호, 소셜 로그인(Google 등)을 지원합니다.

- **위치:** 애플리케이션 진입 시 (로그인하지 않은 상태)
- **역할:** 팀 멤버가 시스템에 자신의 신원을 증명하고 접근 권한을 얻는 과정을 처리한다.

---

### 기능: 로그인

> **목표:** 기존 팀 멤버는 자신의 계정으로 시스템에 안전하게 접근할 수 있다.

**시나리오 1: 구글(Google) 계정으로 로그인 성공**

`Given` 팀 멤버가 로그인 페이지에 있다
`And` 팀 멤버는 구글 계정에 로그인된 상태이다
`When` 팀 멤버가 `Google 계정으로 로그인` 버튼을 클릭한다
`Then` Firebase Authentication 팝업 또는 리디렉션이 발생해야 한다
`And` 인증이 성공적으로 완료되면, 팀 멤버는 '대시보드' 페이지로 이동해야 한다
`And` 우측 상단에는 팀 멤버의 프로필 정보가 표시되어야 한다

**시나리오 2: 이메일과 비밀번호로 로그인 성공**

`Given` 팀 멤버가 로그인 페이지에 있다
`And` 팀 멤버는 "test@example.com" / "password123" 계정을 가지고 있다
`When` 팀 멤버가 이메일 필드에 "test@example.com"을 입력한다
`And` 비밀번호 필드에 "password123"을 입력한다
`And` `로그인` 버튼을 클릭한다
`Then` 팀 멤버는 '대시보드' 페이지로 이동해야 한다

**시나리오 3: 잘못된 비밀번호로 로그인 시도**

`Given` 팀 멤버가 로그인 페이지에 있다
`When` 팀 멤버가 이메일 필드에 "test@example.com"을 입력한다
`And` 비밀번호 필드에 "wrong_password"를 입력한다
`And` `로그인` 버튼을 클릭한다
`Then` "이메일 또는 비밀번호가 올바르지 않습니다." 라는 오류 메시지가 폼 하단에 표시되어야 한다
`And` 팀 멤버는 '대시보드' 페이지로 이동하지 않아야 한다

### 기능: 회원가입 (초대 기반)

> **목표:** 기존 팀 멤버의 초대를 받은 신규 팀 멤버는 시스템에 자신의 계정을 생성할 수 있다. (보안을 위해 공개 회원가입은 허용하지 않음)

**시나리오 4: 초대받은 이메일로 회원가입 성공**

`Given` 관리자가 "new_user@example.com"을 워크스페이스에 초대했다
`And` "new_user@example.com" 예비 팀 멤버는 초대 링크가 포함된 이메일을 받았다
`When` 예비 팀 멤버가 초대 링크를 클릭한다
`Then` 이름과 비밀번호를 설정하는 '회원가입' 페이지로 이동해야 한다
`And` 이메일 필드는 "new_user@example.com"으로 고정되어 수정할 수 없어야 한다

`Given` 예비 팀 멤버가 '회원가입' 페이지에 있다
`When` 이름 필드에 "김새싹"을 입력한다
`And` 비밀번호 필드와 비밀번호 확인 필드에 "password123!"을 입력한다
`And` `가입 완료` 버튼을 클릭한다
`Then` 새로운 팀 멤버 계정이 생성되어야 한다
`And` 팀 멤버는 '대시보드' 페이지로 이동해야 한다

# 2.6.1. SendGrid 웹훅 연동

- **위치:** 이 기능은 특정 UI 페이지가 아닌, 시스템 백엔드와 외부 서비스(SendGrid) 간의 연동을 통해 동작합니다.
- **역할:** 유저의 이메일 수신 거부(Unsubscribe) 또는 반송(Bounce) 상태를 실시간으로 시스템에 반영하여, 더 이상 유효하지 않은 이메일 주소로 메시지를 보내는 것을 방지합니다.

---

### 기능: 이메일 상태 자동 업데이트

> **목표:** SendGrid에서 발생한 이메일 상태 변경 이벤트를 자동으로 수신하여, 해당 유저의 `email_status` 속성을 업데이트하고 불필요한 이메일 발송을 막는다.

**시나리오 1: 유저가 이메일 수신을 거부할 경우 (Unsubscribe)**

`Given` 유저 "user-123"의 `email_status`는 "active"이다
`And` 이 유저는 "월간 뉴스레터" 캠페인으로부터 이메일을 받았다
`When` 유저가 이메일 하단의 '수신 거부' 링크를 클릭하여 SendGrid에서 수신 거부 처리가 완료된다
`And` SendGrid가 우리 시스템의 이벤트 웹훅 엔드포인트로 `unsubscribe` 이벤트를 전송한다
`Then` 시스템은 "user-123" 유저를 식별해야 한다
`And` 해당 유저의 `email_status` 속성은 "unsubscribed"로 업데이트되어야 한다
`And` 유저의 활동 피드에는 "이메일 수신을 거부했습니다." 라는 이벤트가 기록되어야 한다

**시나리오 2: 이메일 주소가 유효하지 않아 반송될 경우 (Bounce)**

`Given` 유저 "user-456"의 `email_status`는 "active"이며, 이메일 주소에 오타가 있다
`When` 시스템이 이 유저에게 이메일을 발송하고, SendGrid가 영구적인 반송(hard bounce)을 감지한다
`And` SendGrid가 이벤트 웹훅 엔드포인트로 `bounce` 이벤트를 전송한다
`Then` 시스템은 "user-456" 유저를 식별해야 한다
`And` 해당 유저의 `email_status` 속성은 "bounced"로 업데이트되어야 한다

---

### 기능: 발송 시 이메일 상태 확인

> **목표:** 캠페인 캔버스에서 이메일을 발송하는 시점에, 대상 유저의 이메일 상태를 확인하여 발송 대상을 필터링한다.

**시나리오 3: 수신 거부 유저에게는 이메일 발송 건너뛰기**

`Given` 유저 "user-123"의 `email_status`는 "unsubscribed"이다
`And` "신규 기능 소개" 캠페인이 이 유저에게 이메일을 보내려고 한다
`When` 유저가 캔버스의 `이메일 발송` 노드에 도달한다
`Then` 시스템은 이메일을 실제로 발송하지 않고, 해당 단계를 `SKIPPED` (사유: `unsubscribed`) 처리해야 한다
`And` 이 기록은 캠페인 성과 분석 페이지에서 확인할 수 있어야 한다

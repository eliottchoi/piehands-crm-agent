# 1.2. 핵심 개념 (상세 버전)

이 문서는 플랫폼의 기본 엔티티(Entity)와 용어를 상세하게 정의합니다. 이 개념들을 이해하는 것은 시스템이 어떻게 작동하는지 이해하는 데 필수적입니다.

## 1. 캠페인 (Campaign)
**캠페인**은 모든 마케팅 활동을 위한 최상위 조직 단위입니다. "신규 사용자 환영" 또는 "비활성 고객 재참여 유도"와 같이, 특정하고 포괄적인 마케팅 목표를 나타냅니다.
- **비유:** 캠페인은 하나의 '프로젝트 폴더'입니다.
- **핵심 속성:** 모든 캠페인은 정확히 하나의 **캔버스**를 포함하며, 이 캔버스가 전체 자동화 워크플로우를 정의합니다.
- (캠페인 생명주기는 기존과 동일)

## 2. 유저 (User)
**유저**는 우리의 고객사(예: 쇼핑몰)가 커뮤니케이션하고자 하는 최종 사용자(end-user)를 나타냅니다.

#### 2.1. 고유 식별자 (Unique Identifier)
- **정의:** 각 유저를 유일하게 식별하는 값입니다. 이 값을 기준으로 신규/기존 유저를 판단하고, 프로필을 병합합니다.
- **필드명:** `distinct_id`

#### 2.2. 속성 (Properties)
- **정의:** 유저의 **현재 상태**를 나타내는 Key-Value 형태의 정보입니다. 이 값은 변경될 수 있습니다.
- **예시:**
  - `name`: "홍길동"
  - `email`: "test@example.com"
  - `level`: "VIP"
  - `email_status`: "active"

#### 2.3. 이메일 수신 상태 (Email Status)
- **정의:** 유저의 이메일 주소 유효성 및 수신 동의 상태를 나타냅니다. 이 값은 SendGrid 웹훅 등을 통해 자동으로 업데이트됩니다.
- **상태 값:**
  - `unknown`: 초기 상태 또는 확인되지 않은 상태.
  - `active`: 유효하며, 수신 동의한 상태.
  - `bounced`: 존재하지 않거나 비활성화된 이메일 주소로 확인된 상태.
  - `unsubscribed`: 유저가 직접 수신을 거부한 상태.

#### 2.4. 이벤트 (Events)
- **정의:** 유저가 특정 시점에 수행한 **행동의 기록**입니다. 이벤트 자체는 불변(immutable)하며, 타임스탬프와 함께 기록됩니다.
- **예시:**
  - `Signed Up` (2025-09-15 10:00:00)
  - `Viewed Product Page` (2025-09-16 11:30:00) - `product_id`: "abc" 속성 포함
  - `Added to Cart` (2025-09-16 11:32:00)
  - `Completed Purchase` (2025-09-17 14:00:00)

## 3. 캔버스 (Canvas) 및 구성요소 (Nodes)
**캔버스**는 캠페인 내의 시각적 워크플로우 디자이너입니다. **노드(Node)**라고 불리는 구성요소들을 연결하여 유저 여정의 로직을 설계합니다.

#### 3.1. 시작 조건 (Triggers)
- **정의:** 캔버스 여정을 시작시키는 진입점 노드입니다. 모든 캔버스는 반드시 하나 이상의 트리거로 시작해야 합니다.
- **종류:**
  - **이벤트 기반:** 특정 이벤트가 발생했을 때 (예: `회원가입 완료`)
  - **시간 기반:** 특정 시간이나 주기에 도달했을 때 (예: `매주 월요일 오전 9시`)
  - **API 호출:** 외부 시스템에서 신호를 보낼 때 (예: `결제 실패` 신호 수신)

#### 3.2. 액션 (Actions)
- **정의:** 시스템이 유저를 위해 또는 유저에 대해 실제로 수행하는 작업 노드입니다.
- **종류:**
  - **이메일 발송:** 특정 템플릿을 사용하여 이메일을 보냅니다.
  - **SMS 발송:** 특정 템플릿을 사용하여 SMS를 보냅니다.
  - **유저 속성 업데이트:** 유저의 속성 값을 변경합니다. (예: `level`을 `GOLD`로 변경)
  - **웹훅 호출:** 외부 API로 데이터를 전송합니다. (예: 쿠폰 서버에 쿠폰 생성 요청)

#### 3.3. 흐름 제어 (Flow Control)
- **정의:** 유저의 여정 경로를 나누거나, 대기시키거나, 실험하는 로직 노드입니다.
- **종류:**
  - **시간 대기:** 다음 단계로 넘어가기 전 일정 시간 동안 기다립니다. (예: `2시간 기다리기`)
  - **조건 분기 (If/Then):** 유저의 속성이나 이벤트 발생 여부에 따라 경로를 나눕니다. (예: `유저의 level이 VIP인가? (Yes/No)`)
  - **A/B/n 테스트:** 유저를 여러 그룹으로 나누어 어떤 메시지나 흐름이 더 효과적인지 실험합니다.

## 4. 템플릿 (Template)
**템플릿**은 캔버스의 `이메일 발송`과 같은 액션 노드에서 사용하는 재사용 가능한 콘텐츠 조각입니다.
- **핵심 속성:** `{{user.name}}`과 같이 유저의 속성을 가져와 개인화된 메시지를 만드는 변수를 포함할 수 있습니다.
